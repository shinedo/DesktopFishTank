# DesktopFishTank

一个 Windows 桌面装饰工具：全屏透明、始终置顶、默认鼠标穿透的荧光玻璃鱼塘。

## 功能

- 铺满整个虚拟桌面（多显示器一起覆盖），始终位于所有窗口最上层
- 默认鼠标穿透，不拦截任何点击；不在任务栏、不占 Alt+Tab
- **荧光玻璃鱼**：半透明体壁、透出的骨骼与内脏、体侧荧光带，全部由 WPF 矢量程序化绘制，不使用贴图
- **荧光磷虾**：透明头胸甲、分节腹部、扇形尾扇、长触须与多对附肢，和鱼共用同一套荧光配色，体型约是鱼的一半
- **荧光水母**：半透明钟形伞盖、放射状辐管、伞缘荧光与拖曳的触手、口腕，靠伞体搏动一冲一冲地前进
- **荧光河豚**：浑圆身体、体表短刺、大眼和快速扇动的小鳍，缓慢悬停
- 20 种荧光配色，可在鱼群设置里逐项勾选启用哪些
- 品种（荧光鱼 / 磷虾 / 水母 / 河豚）可在鱼群设置里逐项开关，混养时鱼最多，河豚最少见
- **吸引快捷键**：按住快捷键时所有鱼转向鼠标位置并加速游过去，默认按住 `Ctrl + Shift`
- **交互快捷键**：按住时临时进入可交互状态，鼠标靠近会把鱼惊走，左键可拖拽鱼，默认按住 `Ctrl + Alt`
- 两个快捷键都能在托盘菜单里改成任意组合（含「只按修饰键」的组合）
- 鱼群整体游速较快，吸引时会明显加速冲向鼠标
- 系统托盘菜单：显示/隐藏、鱼群设置（数量、最大体型、透明度、周围荧光）、帧率（20 / 30 / 60 FPS）、吸引快捷键、交互快捷键、退出
- 单实例运行，重复启动会直接退出
- 配置自动保存，重启后沿用上次的体型、透明度、数量、帧率和快捷键

## 运行

发布版是**自包含单文件**，不需要安装 .NET 运行时，直接把 `publish\DesktopFishTank.exe`
拷到目标电脑运行即可：

```
publish\DesktopFishTank.exe
```

- 系统要求：Windows 10 1607+ / Windows 11，x64
- 普通用户权限即可，不需要管理员，也不联网
- 首次启动会把内置运行时解压到临时目录，约 1–2 秒；之后启动更快

开发运行：

```
dotnet run --project DesktopFishTank.csproj
```

## 构建发布

```
dotnet publish DesktopFishTank.csproj -c Release -o publish
```

发布配置写在 `DesktopFishTank.csproj` 里：Release 自动自包含、单文件、内置原生库并压缩，
产物只有一个约 65 MB 的 exe（`.pdb` 是调试符号，可以不拷）。Debug 构建不会带运行时。

## 操作一览

| 操作 | 效果 |
| --- | --- |
| 什么都不按 | 鱼塘完全穿透，照常使用其他窗口 |
| 按住吸引快捷键（默认 `Ctrl + Shift`） | 所有鱼游向鼠标位置，靠近后绕着鼠标转 |
| 按住交互快捷键（默认 `Ctrl + Alt`） | 鱼塘临时可交互 |
| 左键按住鱼拖拽 | 抓住鱼移动，松开后鱼窜开 |

| 双击托盘图标 | 显示 / 隐藏鱼塘 |
| 右键托盘图标 | 打开设置菜单 |

### 关于鱼的造型

整条鱼由矢量绘制，透明与发光都取真实鱼类的光学特征：

- **透明体壁**：体壁很薄且几乎不着色，桌面会直接透过来；上下缘有一道渐亮的菲涅尔亮边，用来读出圆润的体积。
- **可见的内部结构**：脊椎（一节节椎骨）、肋骨、鳃弓、鳃盖、鳔和肠道透过体壁可见，并且略微滞后于身体摆动。
- **荧光带**：体侧一条从眼后贯穿到尾柄的色带，由外层散光、中层主色、中心亮线三层叠成，带轻微呼吸脉动；体后另有一段暖色软斑。
- **鳍**：半透明薄膜加发光边缘，尾鳍、背鳍、臀鳍、腹鳍、胸鳍都会随游姿摆动；尾鳍不画鳍条线，保持整片薄纱的通透感。
- **动态**：一条很淡的折射光带缓慢扫过体侧，背脊有镜面水光。

### 关于磷虾

磷虾沿用同一套配色，只是换了造型与比例，体型约为鱼的六成：

- **头胸甲与腹部**：前半是宽而透明的头胸甲，后半是六节、越往后越细并向下方弯的腹部，体节线透过甲壳可见。
- **内部结构**：肝胰腺、心脏与贯穿腹部的消化道透过甲壳若隐若现。
- **头部**：眼柄把黑色复眼顶出甲壳外，吻端有额剑，一对长触须和小触角随水流摆动。
- **附肢**：五对胸足与五对桨状游泳足各自错相摆动，频率比鱼鳍快。
- **尾扇**：中央尾节加两对尾肢，随游姿整体摆动，慢游时几乎只是轻轻展开。
- **荧光**：体侧荧光带从眼后贯穿到尾柄，触须与尾扇边缘带一层淡光。

### 关于水母

水母没有头尾，伞顶朝游动方向，伞口和触手向后拖曳：

- **伞盖**：半透明钟形，顶点朝前；伞壁靠伞顶一侧接光，伞腔里有一团柔和的荧光物质。
- **搏动**：伞缘随相位向伞顶收缩、再舒张，同时游速也按同一节律忽快忽慢，是水母特有的脉冲推进。
- **辐管与伞缘**：九条放射状水管从伞顶通到伞缘，伞缘一圈是整只水母最亮的荧光。
- **触手与口腕**：九条细触手和四条褶边口腕向后拖曳，各自错相摆动，游得越慢摆幅越小。

### 关于河豚

- **河豚**：浑圆的身体、贴体的一圈短刺、很大的眼睛和比例很小的鳍；尾柄收窄后接一片圆尾鳍，游速慢、以悬停为主。
- **荧光**：一条横贯体侧的荧光带，加上从头部向尾部扫过的折射光带；扫光在身体轮廓内裁剪，不会溢出体表。

### 外观设置

右键托盘图标：

| 菜单 | 作用 |
| --- | --- |
| 鱼群设置… | 一个窗口里连续调节数量（1–32 条）、最大体型（0.5–3.0×）、透明度（20–100%），开关周围荧光，逐项勾选启用的品种与配色（各至少保留一种）；改动即时生效，关闭窗口时保存 |

- 增减数量时保留已有鱼的位置，例如从 14 调到 15 只新增一条，不会整群重排。
- 最大体型是绘制缩放的硬上限，滑块拉到最右显示「不限制」。
- 关闭「鱼周围荧光」只去掉鱼体外那层环境光晕，鱼自身的荧光带、鳍缘发光仍然保留。
- 每次勾选或取消品种，整池生物都会按新权重重新随机一遍：只勾水母时整池都是水母，再勾上其他品种，水母会立刻混出一部分其他生物。
- 品种按权重随机分配：荧光鱼 50、磷虾 25、水母 15、河豚 10。磷虾体型约为鱼的一半，水母、河豚比鱼略小。
- 所有品种都带体侧荧光带，并有一道**从头部向尾部**扫过的折射光带；荧光颜色跟随当前配色。扫光按各自周期缓慢扫过，每扫完一次会停顿约四分之一周期再开始下一轮。

### 关于快捷键绑定

- 两个快捷键都可在托盘里重新绑定：右键托盘图标 →「吸引快捷键」或「交互快捷键」。
- 支持两类组合：
  - 只按修饰键，例如默认的吸引快捷键 `Ctrl + Shift`、默认的交互快捷键 `Ctrl + Alt`。在绑定窗口点「重新绑定」后，只按住修饰键再松开即可；
  - 修饰键 + 主键，例如 `Ctrl + Alt + F9`。
- 未设置修饰键的单个按键也能绑定，但容易误触，建议至少带一个修饰键。
- 匹配要求修饰键严格一致：绑定 `Ctrl+Shift` 时，`Ctrl+Alt+Q` 不会触发。
- 两个快捷键不能设成同一组：交互快捷键如果被吸引快捷键包含（例如交互设为 `Ctrl+Alt`、吸引设为 `Ctrl+Alt+F9`），吸引期间会优先保持鱼塘穿透。
- 吸引默认只按 `Ctrl + Shift`，按住期间鱼群会被吸引；它也是很多编辑器的组合键前缀，短暂按住会顺带吸引鱼群，介意的话可以改绑带主键的组合。
- 把吸引快捷键设为「未绑定」后鱼群不再响应鼠标；把交互快捷键设为「未绑定」后鱼塘始终保持穿透，无法拖拽鱼。

## 配置文件

```
%LOCALAPPDATA%\DesktopFishTank\settings.json
```

字段：

| 字段 | 说明 |
| --- | --- |
| `FishCount` | 鱼的数量 |
| `MaxFishScale` | 最大绘制缩放，`0.5`–`3.0` 连续可调（`3.0` 表示不限制） |
| `FishOpacity` | 整体不透明度，`0.2`–`1.0` 连续可调 |
| `ShowHalo` | 是否绘制鱼周围的环境光晕 |
| `EnabledPalettes` | 启用的配色名列表；缺省或为空表示全部启用 |
| `EnabledSpecies` | 启用的品种名列表（`荧光鱼`、`磷虾`、`水母`、`河豚`）；缺省或为空表示全部启用 |
| `FrameRate` | 目标帧率 |
| `AttractHotkey` | 吸引快捷键，`VirtualKey` 为 Win32 虚拟键码，`0` 表示未绑定或只按修饰键；默认 `Ctrl + Shift` |
| `InteractHotkey` | 交互快捷键，结构同上；默认 `Ctrl + Alt`（`VirtualKey` 为 0） |

配置损坏或不可写时会回退到默认值，不会影响启动。旧版本配置里已废弃的风格字段会被忽略。

## 性能

透明全屏窗口走的是 WPF 的软件合成路径，开销与屏幕像素数成正比。实测环境
（5120×1440、28 逻辑核心、16 条鱼、30 FPS）：整机 CPU 约 2.5%（折合单核约 0.7 核），
框架依赖发布时工作集约 240 MB；自包含单文件发布因为带着运行时，约 300–330 MB。

鱼数从 4 增到 32 时，单核占用只增加约 5 个百分点：绘制成本主要来自全屏透明表面的
合成，而不是单条鱼。此前每条鱼有两层 `PushOpacity`（光晕 + 鱼身），软件渲染下每个
分组都要离屏合成一次，这才是鱼一多就卡的根因；现在整体透明度只在画布上开一层分组，
100% 透明度时完全不开。

如果觉得占用偏高，可在托盘菜单里切到「省电（20 FPS）」，或者临时隐藏鱼塘
（隐藏后停止渲染）。全屏透明窗口本身无法启用硬件加速，这是 WPF
`AllowsTransparency` 的固有限制。
